# Personal Neural Memory — Phase 0/1 (brain) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase 0 (skeleton: full D1 schema, auth middleware, health endpoint, deploy) and Phase 1 (capture: encrypted R2 payloads, single/batch ingest, budgets + breaker, crypto-shred purge, tombstone-honoring rebuilder, FTS search, blocks, stateless MCP, OpenCode capture plugin with local backstop, `*/30` sweep cron) of the approved Personal Neural Memory design.

**Architecture:** Event-sourced Cloudflare Worker (`brain-api`): append-only `events` metadata in D1, AES-GCM payloads with per-event wrapped keys in R2 (`payloads/{event_id}`), FTS5 keyword projection over redacted excerpts only, three scoped bearer tokens, stateless MCP server (`createMcpHandler`, read + propose only), and an OpenCode plugin that POSTs session transcripts on `session.status` → `idle` with a 30-minute local backstop. Projections are rebuildable from events and must honor purge tombstones.

**Tech Stack:** Cloudflare Workers + TypeScript + Wrangler · D1 + R2 · `@cloudflare/vitest-plugin` (Vitest ≥4.1, tests run in workerd) · `@modelcontextprotocol/server` (`McpServer` + `createMcpHandler`) · zod · `@opencode/plugin` ^2.0.29 (plugin package only).

**Spec:** `/home/taxin/.opencode/plan/README.md` (Design v1.2, APPROVED — the plan argues from it, so executors read both). Only Phase 0/1 deliverables are in scope (spec §8). The SQL in spec §4 is copied into migrations verbatim (split below); it is not re-invented here.

## Global Constraints

- Repo `/home/taxin/Work/brain` (created + `git init` in Task 1). Worker name `brain-api`; D1 database `brain-db`; R2 bucket `brain-raw`.
- Bindings: `BRAIN_DB` (D1), `BRAIN_RAW` (R2). Secrets, exact names: `PAYLOAD_KEK`, `CONTENT_HMAC_KEY`, `MCP_READ_TOKEN`, `MCP_PROPOSE_TOKEN`, `ADMIN_TOKEN`. Prod values via `openssl rand -base64 32`; local dev via gitignored `.dev.vars`; prod via `wrangler secret put`.
- R2 object key is per-event: `payloads/{event_id}`. Content-addressing is forbidden (spec v1.2 amendment 7). `events.content_hmac = HMAC-SHA256(CONTENT_HMAC_KEY, redacted_payload)`, hex.
- Limits: batch ≤ 500 entries; event ≤ 1 MiB (redacted JSON bytes); excerpt ≤ 500 chars. Idempotency by event id **and** by `(session_id, content_hmac)`.
- Trust map: `user` 1.0, `assistant` 0.9, `tool` 0.7, `external` 0.4. MCP `remember` → `actor=assistant`, trust 0.9.
- Budgets (per UTC day): `MCP_PROPOSE` cap 10,000 rows/day → 429; global warn at 70,000; breaker at 80,000 → 503 for non-admin writes. **ADMIN is exempt from cap and breaker** (still counted).
- Confirm tokens: single-use, 5-minute TTL, minted only for ADMIN, and **no MCP response ever contains one**. `restricted` events never appear in MCP responses.
- `events` is append-only (trigger-guarded). The only `UPDATE` allowed is the purge path (`redacted` 0→1, `excerpt` NULL). Purge sequence is exactly spec §4's six steps.
- MCP surface is read + propose only: `recall`, `get_blocks`, `health_report` (read scope), `remember` (propose scope). `forget`, `approve`, `export`, `dispute`, block writes are NOT MCP tools.
- Cron Triggers in Phase 1: only `*/30 * * * *` (sweep: budget counters/warn, prune expired confirm tokens).
- Plugin capture: watch `session.status` events with `status === "idle"` (the non-deprecated signal; event shape `{ type: "session.status", sessionID, status }`), POST not awaited, stable per-message event ids kept in plugin storage; 30-min backstop runs in the plugin (on load + interval). `session ended` = idle ≥ 30 min.
- Tests: Vitest ^4.1 + `@cloudflare/vitest-plugin`; `cloudflareTest({ wrangler: { configPath } })`; migrations applied per test file via `readD1Migrations` (Node side) + `applyD1Migrations` (setup file); secrets are test-only miniflare bindings and tests read token values from `env` (never hardcode).

## Review Focus

Five failure modes the spec implies, each pinned by a test in the owning task:

1. **Two events with identical payloads** — purging one must leave the other decryptable (per-event keys; content-addressing removed for exactly this). → Task 8.
2. **`restricted` material or a confirmation token surfacing in any MCP response** — recall must exclude restricted; no tool output ever carries a token. → Task 11.
3. **The breaker or cap locking ADMIN out of their own brain** — ADMIN passes at any usage level. → Task 6.
4. **Purged material resurrecting when projections rebuild** — rebuild honors tombstones. → Task 9.
5. **Replayed plugin batches double-charging the daily write budget** — dedupe happens before charging; retries are free. → Task 7.

### Task 15: Keyword eval harness (recall@5 regression gate)

Gate: recall@5 ≥ 0.9.

- [x] **Step 1: Seed the eval file with ≥ 10 real pairs**

Derive each `doc`/`q`/`expect` from actual captured sessions (start with the Task 14 live session). No invented content.

- [x] **Step 2: Write the harness test** — `test/eval.test.ts`:

```ts
import { env } from "cloudflare:workers";
import { describe, expect, it } from "vitest";
import pairs from "../eval/keyword.json";
import { searchEvents } from "../src/search";
import type { EventInput } from "../src/ingest";
import { bearer, call } from "./helpers";

describe("keyword eval", () => {
  it("keeps recall@5 at or above the regression gate", async () => {
    for (const [i, p] of pairs.entries()) {
      const res = await call("POST", "/v1/events",
        { source: "manual", actor: "user", kind: "note", session_id: `eval-${i}`, payload: { text: p.doc } } as EventInput,
        bearer(env, "MCP_PROPOSE"));
      expect(res.status).toBe(201);
    }
    let hits = 0;
    for (const p of pairs) {
      const results = await searchEvents(env, p.q, 5, { includeRestricted: false });
      if (results.some((r) => r.excerpt.includes(p.expect))) hits++;
    }
    expect(hits / pairs.length).toBeGreaterThanOrEqual(0.9);
  });
});
```
